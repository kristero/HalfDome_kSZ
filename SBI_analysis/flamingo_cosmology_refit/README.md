# Cosmology response for the FLAMINGO spectral fits

This isolated cluster analysis refits the nine Battaglia-form parameters after
including an approximate response to cosmology. The user selected abundance,
growth and geometry, and previously selected fitting the clean spectra with
noise compared separately. The existing 8,192-row production run is unchanged.

Cluster root:
`/lustre/work/kristero10/flamingo_cosmology_refit_20260915`.
The small verified result export is in `cluster_results/` alongside this file.

## Cosmologies and mass convention

| Quantity | Native HalfDome N-body | Historical HalfDome painter | FLAMINGO D3A |
|---|---:|---:|---:|
| h | 0.6774 | 0.68 | 0.681 |
| Omega_m | 0.3089 | 0.31 | 0.306 |
| Omega_b | 0.0486 | 0.049 | 0.0486 |
| sigma_8 | 0.8159 | inherited halo population | 0.807, rounded |
| n_s | 0.9667 | inherited halo population | 0.967 |
| sum m_nu [eV] | 0 | inherited halo population | 0.06 |

The native values come from the
[HalfDome paper](https://arxiv.org/html/2407.17462v2) and the
[FLAMINGO simulation table](https://flamingo.strw.leidenuniv.nl/simulations.html).
The rounded painter values were verified in the archived workflow. The three
feedback variants here use the same D3A cosmology.

The catalogue stores M200c in Msun/h. The historical painter divides by 0.68;
native physical masses divide by 0.6774. We account for this 0.384% difference in
the response denominator, preserving the actual settings of the existing maps.
Changing distances in the painter alone cannot change the N-body halo abundance.

CAMB 1.5.9 provides linear cold-plus-baryon and total-matter power in physical
units (k in 1/Mpc and P in Mpc^3), H(z), and comoving distance. Native HalfDome
power is normalized to sigma_8 = 0.8159. FLAMINGO uses A_s = 2.099e-9, one 0.06 eV
massive neutrino, two massless species, N_eff = 3.046 and T_CMB = 2.7255 K. Its
computed sigma_8 is 0.8068503941, consistent with the published rounded value.
The massive-neutrino density is included inside the specified Omega_m.

## Pressure and spectral model

The profile convention is

```
P_th(r) / P200 = P0(M,z) q^(-0.3) (1+q)^(-beta(M,z))
q = r / (xc(M,z) R200c)
A(M,z) = A_amp (M200c / 1e14 Msun)^alpha_m_A (1+z)^alpha_z_A
P200 = G M200c (200 rho_crit) (Omega_b/Omega_m) / (2 R200c)
P_e = 0.5176 P_th
```

Here A is P0, xc or beta. Beta is the raw exponent: the asymptotic pressure slope
is -(beta + 0.3). The amplitudes are defined at physical M200c = 1e14 Msun, z = 0.
The line-of-sight projection and projected 4 R200c painting aperture preserve
the existing map definition.

For each cosmology we compute

```
C_ell^1h = integral dz (dV/dz/dOmega) integral dlnM (dn/dlnM) |y_ell|^2
C_ell^2h = integral dz (dV/dz/dOmega) P_cb((ell+0.5)/chi,z)
            * [integral dlnM (dn/dlnM) b(M,z) y_ell]^2
R_b(theta) = D_b^theory(D3A, theta) / D_b^theory(native HD + legacy painter, theta)
D_b^prediction(theta) = D_b^full_HD_map(theta) * R_b(theta)
```

Tinker08 M200c abundances and Tinker10 bias use cold-plus-baryon variance and
mean density, including Delta_mean = 200/Omega_cb(z). This follows the
[cold-component prescription for massive-neutrino cosmologies](https://arxiv.org/abs/1311.1514).
The equations were checked against the installed Colossus 1.3.9 implementation;
see its [mass-function documentation](https://bdiemer.bitbucket.io/colossus/lss_mass_function.html).
One-halo and two-halo terms use the same catalogue mass and redshift support in
both cosmologies to isolate their cosmological response. The projection includes
the signal's 2 arcmin Gaussian beam and the established 40 mode-count-weighted
D_ell bins, ell = 80 through 7979.

Full HalfDome maps retain the exact existing cap mask (f_sky = 0.4, apodization
60 arcmin), pixel sampling and pseudo-spectrum operator. Applying the smooth
binned ratio after masking approximates the mask coupling; it is not an exact
cosmology transformation of the masked sky.

## Fitting and validation

1. Start from the previous full-map spectral fit for each FLAMINGO variant.
2. Retain an amplitude-only candidate: scaling P0 by a scales the entire clean
   y-map by a and its auto-spectrum by a^2. This candidate needs no new painting.
3. Perform two local nine-parameter proposal/refinement rounds. Each round uses
   equal weights in log D_b, a weak 0.005*(u-u_B12) residual regularizer, and a
   radius 0.08 in prior unit coordinates. P0 and xc coordinates are logarithmic.
   The proposal model is calibrated to the previous full map at the current
   point. The optimization limit is 30 function evaluations per round.
4. Paint a fresh full HalfDome map for each proposal, validate its numerical
   columns and finite spectra, and measure the actual clean masked spectrum.
   Noise is generated by the inherited independent-row backend but is excluded
   from the fit. The original FLAMINGO observation noise is unchanged.
5. Re-evaluate every retained candidate at finer halo-model resolution and select
   the lowest measured fractional RMS, including the amplitude-only candidate.

The fit uses the currently approved conditioned prior, including beta(M,z) <= 50.
The retained older fgas-8sigma and Mstar-1sigma proposals used a beta cap of 40;
the retained older L1_m9 proposal used a cap of 64. Therefore shifts along the
nine-parameter degeneracies cannot all be attributed to cosmology. The
amplitude-only diagnostic separates the approximate cosmological normalization
effect from the larger freedom of a full refit. No paired no-cosmology refit with
identical search settings was performed.

Initial numerical checks passed:

- Tinker abundance and bias equations agree with Colossus at all 18 checked
  overdensity/redshift combinations (four variance values per combination).
- An independent integral of the total-matter spectrum reproduces CAMB sigma_8
  to better than 0.020% in both cosmologies.
- Raising mass/redshift quadrature from 32/24 to 48/36 and minimum radial order
  from 128 to 256 changes the response by at most 0.086% at Battaglia12 and
  0.054% at the three previous FLAMINGO fits. Each new candidate must independently
  pass a 0.5% response-resolution threshold.
- Radial order also increases with angular halo size to resolve nearby-halo
  Hankel oscillations. The high-k two-halo tail continues the measured power
  slope rather than silently clamping to the interpolation boundary.
- P0 cancels from the response to floating-point precision, as required by its
  exact multiplicative role in y.

See `cluster_results/audit/response_check.json`, the individual `*_fit.json`,
`*_status.json`, `*_support.json`, and proposal JSON files for measured results
and optimizer termination flags. An iteration limit is not convergence, and
full-map verification of the HD part is not validation of the cosmological
response against an independent N-body simulation.

## Interpretation for the extended dataset

These are approximate FLAMINGO-cosmology-equivalent pressure parameters. A
network trained on unchanged HalfDome cosmology still infers HalfDome-effective
parameters. The corrected values should not be substituted for those parameters
without changing the forward model used for training and inference.

A future cosmology-aware pipeline should apply the chosen response to the clean
signal before adding the unchanged SO noise and before constructing/compressing
the SBI summaries. Multiplying a noisy spectrum by R also rescales its noise
terms and is not the specified observation model. An exact map-level correction
requires more than this approximate binned-power response. MOPED and SBI must
be checked or retrained under the resulting forward model.

The current correction does not remove realization/sample-variance differences,
the FLAMINGO map redshift cutoff versus the longer HD catalogue, lensing choices,
gas outside the painted halo population, or hydrodynamic mass changes. The
Tinker prescription and smooth-mask response have modeling uncertainty beyond
their numerical integration error. A good 40-bin match does not uniquely
determine nine pressure coefficients or establish a physical feedback model.
In particular, applying the Tinker08 redshift dependence above z = 2.5 extends
beyond the redshift outputs used in its calibration
([original paper](https://arxiv.org/html/0803.2706)); the catalogue extends to
z = 3.855. This extrapolation is kept identical in the two cosmologies, but that
does not establish its accuracy for the response.

## Files and rerunning

New source files in this directory:

- `cosmologies.json`: explicit native, painter and target settings.
- `background.py`: CAMB power, distances, units and normalization provenance.
- `halo_response.py`: abundance, bias, pressure projection and cosmology ratio.
- `check_response.py`: independent equation, normalization and resolution checks.
- `audit_ell.py`: additional three-versus-nine-node multipole integration check
  at the previous fits and every retained new candidate; fitting files untouched.
- `refit.py`: prior-constrained proposals, full-map checks and final selection.
- `run_analysis.pbs`: isolated cluster background/check and refit jobs.
- `report.py`: CSV/JSON values, compact plotting data, and PNG/PDF figures.
- `finalize.py`: validate finished maps and prior support, then export artifacts.
- `run_finish.pbs`: run the final integration audit and export after the fits.
- `README.md`: this methodological description.

The cluster `code/` also contains frozen copies of ten existing support files
from the prior pilot and extended production workflow. Those source workflows
were not edited. `manifest.json` records their hashes and the original inputs;
the final export has a separate artifact manifest.

Example submission (use an already staged, isolated root):

```bash
qsub -v RUN_ROOT=/lustre/work/kristero10/flamingo_cosmology_refit_20260915,TASK=background \
  /lustre/work/kristero10/flamingo_cosmology_refit_20260915/code/run_analysis.pbs
qsub -v RUN_ROOT=/lustre/work/kristero10/flamingo_cosmology_refit_20260915,VARIANT=L1_m9 \
  /lustre/work/kristero10/flamingo_cosmology_refit_20260915/code/run_analysis.pbs
```

Refits require a passed response check and verify the frozen manifest. Run the
three variants in at most two concurrent lanes alongside the production jobs.
Scripts resume existing proposals/results: use a new root when changing physics
or optimization settings. The final report can be regenerated from an exported
bundle with `python report.py --root cluster_results`.
