1. Lee22 profile corrections

Lee, Coulton, Thiele and Ho (2022, MNRAS 517, 420; arXiv:2205.01710, hereafter Lee22) fitted generalised NFW profiles to the mean electron density and electron pressure of IllustrisTNG-300 halos. HalfDome uses these fits, written in XGPaint's profile conventions, to paint FRB dispersion measures (density), kSZ (density) and tSZ (pressure). This section explains every correction that was applied to the printed fits between 2026-08-31 and 2026-10-01, why each was needed, how it was found, how the code implements it and how it was verified. The final products multiply the printed pressure by (1+z)2 and the printed density by [0.6774 (1+z)]3 XH2. Neither factor is fitted. The (1+z) powers follow from the units of Lee22's public extraction code (an identity of that code for the pressure, an inference for the density, whose normalisation step is not public) and are confirmed by the redshift trends of CAMELS-TNG and FLAMINGO. The constant h3XH2 of the density is inferred from the code units and the hydrogen convention of the paper's n200, and is selected by the CAMELS-TNG gas. No correction required an edit to XGPaint. The XGPaint behaviours that the corrections rely on, or work around, are marked in the XGPaint boxes.

Key result

The printed Lee22 fits are low by a3 (density) and a2 (pressure), a = 1/(1+z), because the extraction code divides by comoving shell volumes but normalises with the physical critical density (for the density this is inferred). The printed density is also too high by a constant, 1/(h3XH2) = 5.57: 1/h3 from the code's h-scaled length unit and 1/XH2 from the hydrogen convention of n200. After both corrections the Lee22 pressure matches the TNG model to FP = 0.99–1.07 (1013.5–1014 M☉, z = 0–1.5), and the Lee22 density reproduces TNG300's mean halo DM per hit ray from 1013–1014 M☉ halos to 0.98–1.02 at zs = 0.1–3. The previous production density (×0.6016) was 2.85× too high at zs = 0.1.

1.1 What Lee22 fitted, and how HalfDome uses it

Lee22 stacked the gas around halos of TNG300, the largest IllustrisTNG hydrodynamical box (205 h-1 Mpc on a side). The halo centres and masses are not taken from the hydrodynamical run itself. They come from a catalogue made with the Rockstar halo finder (which groups particles in phase space) on the matching gravity-only (GO) run, that is, the same initial conditions evolved with dark matter only. The radial coordinate is x = r/R200c. Here R200c is the radius inside which the mean density is 200 times the critical density ρcr(z) of the universe at the halo redshift, and M200c is the mass inside that radius. TNG stores masses in units of h-1 M☉, where h is the Hubble constant in units of 100 km s-1 Mpc-1 (h = 0.6774 for TNG). A mass "1013 h-1 M☉" is therefore 1.48 × 1013 M☉.

Both quantities are fitted with the same generalised NFW (gNFW) shape. A gNFW profile is a broken power law: it falls slowly, as xγ with γ = −0.3, inside a core radius xc, and much more steeply outside it. In the paper's eq. (10):

ne(x) / n200 = n0 (x/xc′)γ [1 + (x/xc′)α]−β′ ,    Pe(x) / P200 = P0 (x/xc)γ [1 + (x/xc)α]−β ,    α = 1, γ = −0.3

The two normalisations are defined in eq. (9):

n200 = 200 ρcr(z) fb / (XH mp) ,    P200 = 200 G M200c ρcr(z) fb / (2 R200c) ,    ρcr(z) = 3H02[Ωm(1+z)3 + ΩΛ] / (8πG)

Here fb = Ωb/Ωm is the cosmic baryon fraction, XH = 0.76 is the hydrogen mass fraction of primordial gas, and mp is the proton mass. P200 is the "self-similar" pressure of gas at 200 fb ρcr and the virial temperature; it is the same P200 as in Battaglia et al. (2012, hereafter B12). n200 is a reference number density. Each fit parameter A ∈ {n0, xc′, β′} or {P0, xc, β} is a power law in mass and redshift, A = A0 (M/Mcut)αm (1+z)αz, and the mass slope can change at Mcut (a "broken power law", BPL). HalfDome uses the fits without concentration: arXiv Table 8 for the density (MNRAS Table A2; Mcut = 1013.61 h-1 M☉, break in xc′ and β′) and Table 7 for the pressure (MNRAS Table A1; Mcut = 1013.60 h-1 M☉, break in P0). For example, n0 = 6.8 (M/Mcut)0.68 (1+z)−2.11 and P0 = 2.8 (M/Mcut)1.08 (1+z)−1.89 below Mcut, with mass slope 0.80 above it.

function lee2022_pressure_parameters(model::Lee2022ThermalSZProfile, mass_msun::Real, z::Real)
    mass = Float64(mass_msun); z1 = 1.0 + Float64(z)
    mcut = LEE22_PRESSURE_MCUT_HINV_MSUN / Float64(model.cosmo.h)
    ratio = mass / mcut
    p0 = 2.8 * (ratio < 1 ? ratio^1.08 : ratio^0.80) * z1^(-1.89)
    shape_ratio = min(mass, model.shape_clip_mass_msun) / mcut
    x_c = 2.10 * shape_ratio^(-0.35) * z1^0.53
    beta = 9.4 * shape_ratio^(-0.06) * z1^0.60
    return (P0=p0, x_c=x_c, alpha=1.0, beta=beta, gamma=-0.3, mass_cut_msun=mcut)
end

function XGPaint.get_params(model::Lee2022ThermalSZProfile{T}, M_200c, z) where {T}
    p = lee2022_pressure_parameters(model, Float64(M_200c / XGPaint.M_sun), z)
    return (xc=T(p.x_c), α=T(p.alpha), β=T(p.alpha * p.beta - p.gamma), γ=T(p.gamma),
            P₀=T(p.P0 / LEE22_PRESSURE_ELECTRON_TO_THERMAL))
end

The fitted range. Lee22 used 0.2-dex mass bins in which each concentration quartile holds more than 29 halos, 27 radial bins between 0.04 and 1.34 R200c, and the TNG full snapshots at z ≤ 2. The paper says that halos were binned in "the 20 full IllustrisTNG snapshots"; 10 of them have z ≤ 2. The populated bins run from 1013.0 to about 1014.0 h-1 M☉ at z ≤ 0.2 (the text says "up to M = 1014 h-1 M☉"), about 1013.6 at z = 1 and 1013.2 at z = 2. Earlier project documents and the code constants quote 1014.8 h-1 M☉ as the upper limit of the fit. The 2026-10-01 verification found that this number appears nowhere in the paper; it was a misreading (outputs/lee22_verify_v3_20261001/completeness_critic/edits.json; doc v4 Sec. 1). The value is kept only as the production shape-clip threshold.

Where HalfDome uses the fits. The density enters the FRB dispersion measure, DM = ∫ ne dl/(1+z) (pc cm-3, observer frame), along rays through each halo's R200c sphere, and the kSZ optical depth. The pressure enters the Compton parameter y = (σT/mec2) ∫ Pe dl of the tSZ maps. All three are built on XGPaint (the kristero/XGPaint.jl fork of WebSky-CITA/XGPaint.jl). The Lee22 profile is supplied by the repository as a new profile type that overrides XGPaint.get_params (for the pressure also the per-(M, z) y evaluation helpers that XGPaint defines for its own Battaglia type, lee2022_tsz_pressure_profile.jl:60-79). XGPaint's gNFW shape, its line-of-sight integral (used for the tSZ maps) and its lookup-table interpolators are used unchanged. The painting loops themselves (lee22_tsz_corrected/paint_tsz_variants.jl, lee22_tsz_corrected/ksz/paint_ksz_variants.jl) are project code that call XGPaint's interpolators and HEALPix ring helpers. The FRB rays and the kSZ maps count only gas inside a sphere (R200c for the rays, 4 R200c for kSZ), so their line-of-sight integral is a project-side chord through that sphere (for the rays chord_dm_pc_cm3 and SphericalChordDMProfile, lee2022_frb_dm_profile.jl:679-743; for kSZ ChordMeanProfile, truncation_comparison/spherical_truncation_profiles.jl), evaluated on the same 3-D density and tabulated with XGPaint's interpolator.

1.3 Transcription and convention fixes

1.3.1 C1: the n0 pivot

Symptom. On 2026-09-16 the line-by-line transcription check found that the no-concentration fit and the full (concentration) fit disagreed by 35–40 % at 1013.75 h-1 M☉ (the Mcut of the concentration fit, Table 3; z = 0), although they describe the same halos. Cause. The original code evaluated the no-concentration n0 about a pivot of 1014 M☉, while xc′ and β′ used Mcut. The paper's eq. (12) states that the three density parameters share Mcut, and a parameter without a second slope is a single power law about it. Fix. Option n0_pivot=:mcut (line 372 above). It raises the no-concentration amplitude by (1014 h/1013.61)0.68 = 1.42 and brings the two fits to n0 = 8.5 versus 9.2–10 at 1013.75 h-1 M☉ (LEE22_IMPLEMENTATION_CHECK_20260916.md, item 1). Verification. Against the vector curves drawn in Lee22's own Fig. 5, a 1014 pivot gives 0.55–0.56 of the drawn density, the Mcut pivot 1.02–1.04 (outputs/lee22_verify_v3_20261001/fig2fig5_content/lee22_fits_vs_drawn.txt). The constructor default is still :legacy_1e14, so that the historical cache signatures do not change. Every production call passes :mcut explicitly.

1.3.2 C2: the exponent convention β′ → βXG = αβ′ − γ

Question. Lee22 write the outer factor as [1 + (x/xc)α]−β′, so β′ is the exponent itself. XGPaint's shared shape function uses a different parameter, the asymptotic outer slope β:

XGPaint: f(x) = x̄γ (1 + x̄α)−(β+γ)/α ,  x̄ = x/xc   ⇒   −(βXG+γ)/α = −β′  ⇔  βXG = αβ′ − γ = β′ + 0.3

At large x both forms then fall as xγ−αβ′. The same mapping is what XGPaint itself applies to B12. The alternative readings, in which the printed β′ is already an asymptotic slope, give exponents −(β′ − γ)/α or −(β′ + γ)/α.

Verification. doc/check_beta_convention.py evaluates the three readings against the vector paths of the paper's own fit curves (Fig. 2 for Pe, Fig. 5 for ne; both z = 0 mass bins, 0.04–1.34 R200c). It reports min and max of model/paper. The ratio max/min − 1 measures a tilt in shape:

The printed convention reproduces the drawn shapes to 0.3–3 % with a 0.5–3.6 % constant offset. The alternatives tilt the curves by 6–19 %. With the mass moved by at most 0.015 dex and a free amplitude, the drawn curves are reproduced to less than 0.05 % (doc v4 Sec. 1), so the remaining offset is the rounding of the printed parameters. Lee22's β′ is therefore not a typo: it is the exponent their own curves use. The mapping is exact at the parameter level: run_lee2022_xgpaint_self_test checks (β+γ)/α = β′ to 10-12, and that XGPaint's projected DM chain on the wrapper reproduces the repository's own Lee22 column to 2 × 10-6 (lee2022_frb_dm_profile.jl:835-870).

XGPaint behaviour: the gNFW exponent changed in the fork (9f37b1e), and the first Lee22 code did not follow

The exponent −(β+γ)/α is not upstream XGPaint's original form. Upstream main (as fetched, 29ec48a) writes (1 + x̄^α)^((β - γ) / α) together with "Sigurd's conversion" β = γ - α * β for B12; the two together give the B12 exponent −β. Commit 9f37b1e (Adrian Bayer, upstream branch adrian, 2026-02-27; merged into the fork in b924ab1, 2026-03-02) changed src/profiles_y.jl to (1 + x̄^α)^(-(β + γ) / α) # correction to battaglia 2016 tau. and the B12 conversion to β = - γ - α * β; in src/profiles_tau.jl it also flipped Battaglia16's β amplitude from −3.83 to +3.83, which leaves the Battaglia16 shape unchanged (Section 1.8). With the new exponent that is −(−γ − αβ + γ)/α = +β, an outer factor (1+x̄)+β. Fork commit e67a8a1 (2026-04-30) fixed it to β = α * β_raw - γ, the line shown below. The buggy sign is not in the B12 lookup table used here: at 20 test nodes the local copy of the stored table equals the correct-sign profile to stored/correct = 1 + (0.4–13) × 10-9, whereas the buggy sign would differ by factors of 1029–1040 (outputs/lee22_verify_v3_20261001/code_snippets/b12_cache_sign_test.json). The idark copy that painted the maps was not read byte for byte, but the maps' B12/FLAMINGO power of 0.70–0.80 (Section 1.11) excludes the buggy profile (doc v4 Sec. 1).

Effect on Lee22. The first Lee22 implementation (commits 2c6d3b6, 2026-08-27, to 7f70174, 2026-08-30) copied the legacy upstream conversion, beta_standard = parameters.gamma - parameters.alpha * parameters.beta_prime, with the comment "(beta_standard - gamma) / alpha = -beta_prime". It then called XGPaint._nfw_profile_los_quadrature. That comment holds for upstream's old exponent. With the fork's exponent the profile became (1+x̄)+(β′+0.6), which grows outwards, so the line-of-sight integral to 105 R200c blew up. Commit 2771265 (2026-08-31, "lee22 fix for exp DM values") replaced the call by a profile-owned integrand with the paper's −β′ exponent (lee2022_dimensionless_density). On 2026-09-17, commit 6fa5373 put Lee22 back into XGPaint's own chain through get_params with βXG = αβ′ − γ. That mapping is correct for the exponent the fork has carried since the merge b924ab1 (unchanged at the current HEAD 1660e08); with upstream's original exponent (β − γ)/α it would be wrong.

function generalized_nfw(x, xc, α, β, γ)
    x̄ = x / xc
    return x̄^γ * (1 + x̄^α)^(-(β + γ) / α)    # correction to battaglia 2016 tau.
end

function _generalized_scaled_nfw(x̄, α, β, γ)
    return x̄^γ * (1 + x̄^α)^(-(β + γ) / α)
end


function get_params(model::Battaglia16ThermalSZProfile{T}, M_200, z) where T
	z₁ = z + 1
	m = M_200 / (1e14M_sun)
	P₀ = powerlaw_value(model.P0, m, z₁)
	xc = powerlaw_value(model.x_c, m, z₁)
	α = powerlaw_value(model.alpha, m, z₁)
	β_raw = powerlaw_value(model.beta, m, z₁)
    γ = powerlaw_value(model.gamma, m, z₁)
    # Battaglia parameterizes the outer factor as (1 + x^α)^(-β_raw), while
    # generalized_nfw expects the asymptotic outer slope directly. Matching the
    # large-radius behavior x^(γ - αβ_raw) = x^(-β) gives β = αβ_raw - γ.
    β = α * β_raw - γ
    return (xc=T(xc), α=T(α), β=T(β), γ=T(γ), P₀=T(P₀))
end

1.3.3 C3: electron pressure, not thermal pressure

B12 fit the thermal pressure Pth of all particles, and XGPaint converts every pressure profile into electron pressure with a hard-coded Pe = 0.5176 Pth (XGPaint.jl/src/profiles_y.jl:128, upstream code). The factor is the electron share of the particle number in fully ionised gas with XH = 0.76. Lee22 fitted Pe directly. To get Pe out of XGPaint, the wrapper must therefore pass P0XG = P0Lee/0.5176 (line 50 of the pressure excerpt). This is a project-side wrapper choice, not an XGPaint edit. Verification. run_lee2022_tsz_self_test checks the mapping against the printed formula to 10-12. It also checks the XGPaint y against an independent eq. (9)–(10) line-of-sight integral to 10-6, and the interpolator fast path to 10-9. It printed "PASS" at the start of the 2026-09-30 idark run (outputs/lee22_corrected_20260930/logs/selftest_600152.idark.log, line 4). Without the division, the Lee22 maps would come out 0.5176 times the fitted pressure, i.e. 1.93 times too low.

1.3.4 C4: h-1 masses and the painter cosmology

Lee22's Mcut values are in h-1 M☉ with TNG's h = 0.6774. The painters convert them with their own h = 0.68 (mass_cut_msun = 10.0^13.61 / h). The painters also use Ωb = 0.049 and Ωc = 0.261 (Ωm = 0.310), while the HalfDome simulation cosmology is h = 0.6774, Ωm = 0.3089, Ωb = 0.0486 (tau_ksz_comparison/README.md). The same h = 0.68 converts the catalogue masses (M = f["halo_mass_m200c"] at paint_tsz_variants.jl:237, mass = Float64.(M[idx]) ./ H_VALUE at line 243). For Lee22 the mismatch shifts the mass scale by 0.68/0.6774 = 1.004, which is negligible next to the corrections below. For the tSZ maps as a whole, the painter cosmology matters at the 2 % level: a B12 map painted with h = 0.6774 gave a B12/FLAMINGO ratio 2 % lower (LEE22_TSZ_VERIFICATION_20260929.md, Sec. 3). It was kept so that all production caches stay consistent.

1.3.5 C5: the mass range and the shape clip

Symptom. Above Mcut the concentration fit's β′ falls as M−1.10. For M200c above about 2 × 1015 M☉ the outer slope β′ − γ then drops below 1, and the projected column ∫nedl diverges. HalfDome has 14 foreground halos above that mass and 868 above 9.3 × 1014 M☉ for rays to zs = 1 (LEE22_IMPLEMENTATION_CHECK_20260916.md, item 4). The no-concentration fits used in production are milder: above Mcut their outer exponents fall only as M−0.18 (density β′, Table 8, lee2022_frb_dm_profile.jl:377-379) and M−0.06 (pressure β, Table 7, lee2022_tsz_pressure_profile.jl:43). For them the clip is a guard against extrapolating the shape far beyond the fitted bins, not a cure for a divergence. Fix. The shape parameters (xc, β, and xc′, β′) are frozen at the clip mass 1014.8/0.68 = 9.28 × 1014 M☉ (LEE2022_SHAPE_MASS_CLIP=fit → generate_halfdome_z1_dm_mass_windows.jl:187; LEE22_FIT_MAX_MSUN in paint_tsz_variants.jl:34). The amplitudes n0 and P0 keep their fitted mass slopes. Consequence. The clip keeps every profile finite, but the amplitude is still extrapolated about 0.8 dex beyond the fitted bins. For the pressure, P0 ∝ M0.8 with a frozen shape gives a per-halo Y/YB12 of 1.03, 1.52 and 2.72 at 6.3 × 1014, 1015 and 2 × 1015 h-1 M☉. The 1,211 halos above the clip in the full tSZ painting catalogue (the 868 quoted above counted only the foreground halos of the zs = 1 rays) carry most of the Lee22 excess over B12 at low ℓ: in the printed-pressure map, the 35 of them at z < 0.1 carry about 95 % of the ℓ = 100 excess. Before any corrected map was painted, they were estimated to carry 84, 73 and 49 % of the corrected map's excess over B12 at ℓ = 300, 1000 and 3000 (LEE22_TSZ_VERIFICATION_20260929.md, Sec. 3–4; Section 1.11). The code comments in lee2022_tsz_pressure_profile.jl:9 and :94 still describe 1014.8 as the fit range and quote "20 TNG300 snapshots". Both statements are superseded by the reading above.

1.4 The density normalisation before M1: a sequence of readings

The density problem was visible from the first comparison with TNG. The TNG reference was the TNG300 halo-DM catalogue of R. Konietzka (pre-release arrays of per-ray DM from gas inside each halo's R200c sphere, split by halo mass). It was compared with 120,000 HalfDome rays to zs = 1 that count gas only inside each halo's R200c sphere (a "chord" through the sphere). function XGPaint.get_params(model::Lee2022XGPaintDMProfile{T}, M_200c, z) where {T}

    redshift = Float64(z)
    pars = lee2022_parameters(model.lee, mass_msun, redshift)
    beta = pars.alpha * pars.beta_prime - pars.gamma
    zfac = lee2022_redshift_scaling_factor(model.lee, redshift)
    if model.lee.normalization == :xgpaint_ne2d
        # XGPaint-native: the dimensionless Lee22 profile is the gas density in units of 200 f_b rho_cr;
        # no Lee22-side hydrogen factor, XGPaint's ne2d supplies the electron conversion.

    end

function rho_2d(model::AbstractBattagliaTauProfile, r, m200c, z)
    par = get_params(model, m200c, z)

function ne2d(model::AbstractBattagliaTauProfile, r, m200c, z)
    me = constants.ElectronMass
    mH = constants.ProtonMass
    mHe = 4mH
    xH = 0.76
    nH_ne = 2xH / (xH + 1)
    nHe_ne = (1 - xH)/(2 * (1 + xH))
    factor = (me + nH_ne*mH + nHe_ne*mHe)
    result = rho_2d(model, r, m200c, z)  # (Msun) / (Mpc)^2
    return 0.9 * result / factor
end

The redshift problem. Reading E matched TNG at zs = 1, but no constant factor could make the implied gas fraction physical at z = 0 and TNG-like at z = 0.5. Read literally, the printed amplitude falls as n0 ∝ (1+z)−2.11 relative to ρcr(z) (a factor 4.3 from z = 0 to 1 at fixed shape), and together with the redshift dependence of xc′ and β′ the enclosed gas fraction at fixed mass falls by a factor of about 7: from 3.07 to 0.46 fb at 3 × 1013 M☉ and from 4.63 to 0.63 fb at 1014 M☉ (LEE22_NORMALIZATION_EQ7_EQ9_NOTE_20260917.md, Sec. 5 table; the note's text quotes 3.4, which its own table does not support; Fig. 1.1a shows the same fall). The 2026-09-22 audit against the paper's own Fig. 5 found reading E 38 % below Lee22's drawn curve, while the paper's normalisation agrees to 2–3 % (outputs/lee22_fig5_audit_20260922/REPORT.md). Reading E therefore was not Lee22. It was an empirical variant that happened to match one TNG test. The 2026-09-28 forensic investigation measured the TNG300 halo electrons of the Konietzka catalogue, divided by the printed model, in 0.1-wide halo-redshift slices (the catalogue records halo DM on the same rays at 55 source redshifts, so differences between neighbouring source redshifts isolate each slice). The correction adopted in the code, C(z) = 0.284 (1+z)2.48 (option :tng_calibrated, commit c19bd20), was fitted to the cumulative halo DM at zs = 0.1–2 with 0.8 % rms. A constant ratio was rejected: fitted to the slices it gives χ2 = 22337 for 19 degrees of freedom, against 357 for 18 with the power law (outputs/lee22_normalization_forensics_20260928/FINAL_REPORT.md, Sec. 4.2). Against that fit, the 0.6016 was right only near z ≈ 0.35, where most of the zs = 1 DM comes from (Fig. 1.1). Against the final derived correction the crossing is at z = 0.50 (Section 1.9). The same investigation also identified, in the public extraction code, the cause behind the trend.

Why the pressure needs no constant. y_prof.cpp computes P200 inside the code, in the same units as the profile. The hbook table shows both carrying 1/h2 (Pe,code ∝ a3/h2, P200,code ∝ a/h2), so h cancels and only a2 survives. FLAMINGO's 1.2 is a real difference between the two simulations: FLAMINGO groups have about 20 % lower pressure than TNG groups (doc v4 Sec. 3).

Why the density does. The density counts are per (ckpc/h)3 and were normalised outside the public code. If they were divided by a physical, h-free n200 in kpc-3, the stored ratio is ntrue(a/h)3/n200: low by a3 (that is M1) and high by 1/h3 = 3.22. The remaining factor is the hydrogen convention. The paper counts electrons as V ne = xe m XH/mp = xe × (number of hydrogen nuclei). The natural normalisation is then the hydrogen density nH,200 = 200 ρcr fb XH/mp. 1.7 Why the empirical C(z) was superseded: what the TNG catalogue arrays contain

C(z) = 0.284 (1+z)2.48 reproduced Konietzka's "1013–1014" array to 0.8 % rms. Yet it disagreed with the bookkeeping form (1+z)3/Fn in both level and slope: for Fn = 5.4, the 2026-10-07 rerun of the unit test prints the ratio (1+z)3/Fn ÷ C(z) as 0.652, 0.761, 0.932 and 1.150 at z = 0, 0.35, 1 and 2 (scripts/lee22/test_bookkeeping_option_run_20261007.log). It also implied that TNG300 halos hold more electrons than the TNG model itself: 1.55 times the CAMELS R200c electron count at z = 0.05, falling to 0.95 at z = 1.45 (outputs/lee22_konietzka_check_20260930/README.md, Sec. 3). No boundary or electron convention could explain that excess (Fig. 1.8, panel c). The explanation is in the arrays. On every ray and at every one of the 55 source redshifts, DM(10to14) = DM(10to12) + DM(13to14) holds to 9.1 × 10-13 pc cm-3. The same identity built from the nominal windows fails on at least 13.5 % of rays (outputs/lee22_verify_v4_20261001/frb_decades/report.txt). The identity requires the upper edge of "10to12" to be the lower edge of "13to14", i.e. 1013. The hit fractions fix the remaining edges: the difference DM(10to14) − DM(10to13) is non-zero on 2.0, 8.3 and 11.7 % of rays at zs = 0.1, 0.5 and 1, the rate HalfDome's 1014–1015 M☉ halos give (2.0, 8.7, 11.9 %), not the 1013–1014 rate (doc v4 Sec. 3). Each "AtoB" array therefore spans [10A, 10B+1) M☉, and the "13to14" array holds halos of 1013–1015 M☉. The true 1013–1014 decade is DM(10to13) − DM(10to12), ray by ray.

Code: frb_map_generation/lee22_tsz_corrected/tng_windows.py:9-28 maps each HalfDome window label to the difference of two catalogue arrays (for example "m1e13_to_1e14": ("m1e10_to_1e13", "m1e10_to_1e12", ...)) and zeroes the 10-13 round-off of identical sums. identity_residual (lines 31–34) is the test above. The convention is inferred from the arrays and should be confirmed by R. Konietzka.

Consequence for the earlier "matches". Reading E's match (138.6 against TNG's 138.6, Section 1.4) and the C(z) calibration both used the cluster-containing array. Against the true decade, C(z) is 1.51, 1.42 and 1.35 times too high at zs = 0.1, 0.5 and 1, and reading E is 2.85, 1.86 and 1.36 times too high. The derived density gives 0.978, 1.004, 1.024, 1.019, 1.017 and 1.007 at zs = 0.1, 0.5, 1, 1.5, 2 and 3. The statistical errors are 0.4–1.3 % for TNG and 0.4–1.0 % for the rays (verify_v4 frb_decades/report.txt). Battaglia16 drifts from 1.02 to 0.86. Figure 1.9 shows the full PDFs; they are discussed in Section 2.

1.8 The Battaglia curves drawn in Lee22, and the Battaglia16 typos that XGPaint does not have

Why did Lee22 themselves not notice a factor 5.6 in their density? Their figures compare TNG with Battaglia reference curves, and those curves are themselves mis-normalised in compensating directions. Read from the vector figures (outputs/lee22_verify_v3_20261001/fig2fig5_content/battaglia_curves.txt):

  • The B12 curve in Fig. 2 is the thermal pressure, with the h-1 M☉ bin mass used as M☉. That reading matches the drawn curve to 0.2 % (model/drawn 0.998–1.003 in both bins). It is 1/0.5176 = 1.93 times B12's own electron pressure, the quantity the simulation curve shows.
  • The Battaglia16 curve in Fig. 5 is Battaglia (2016)'s appendix formula exactly as printed: ρgas = ρcrρfit without fb, exponent −(β−γ)/α, plotted in units of 200 fbρcr with the h-1 mass as M☉. The shape matches to 0.1 % rms (median ratio 1.002); a free constant gives 0.03171 against 1/(200 fb) = 0.03178.

Both departures are typos in Battaglia (2016) itself, which Lee22 copied. The exponent: that paper's own Fig. A1 curves are reproduced by its Table A1 only with −(β+γ)/α, model/curve 0.984–0.998 in the four mass bins between 7 × 1013 and 2 × 1014 M☉ (0.995–1.010 at 2–3 × 1014 and 1.02–1.08 in the widest bin, 3 × 1014–2 × 1015), against 0.575–0.99 (median 0.78–0.82 per bin) with the printed exponent −(β−γ)/α. The fb: as printed, the formula puts Mgas(<R200)/M200 = 0.511 = 3.25 fb into a 1014 M☉ halo, more gas than the halo's baryon budget; with fb and the corrected exponent it gives 0.110 = 0.70 fb (fig2fig5_content/b16_own_convention.txt). The drawn Battaglia16 curve is therefore 1/fb = 6.4 times too high and has a tilted outer slope. Against such a reference, a density 5.6 times too high does not stand out; the forensic report concluded that the paper's comparison could not have revealed the bookkeeping error or Fn (LEE22_NORMALIZATION_FORENSICS_20260929.md, item M3).

Battaglia16 in XGPaint: the exponent was already right upstream, the fb came with 9f37b1e

HalfDome's Battaglia16 contains neither typo, but the two corrections have different histories. Exponent. Upstream main (as fetched, 29ec48a) evaluates (1 + x̄^α)^((β - γ) / α) with β = -3.83 * m^0.04 * z₁^(-0.025). With the negative β this equals −(|β| + γ)/α, which is already the corrected exponent. Commit 9f37b1e (Adrian Bayer, 2026-02-27, branch adrian of WebSky-CITA/XGPaint.jl; in the fork since b924ab1) rewrote it as -(β + γ) / α with β = +3.83 and the comment "correction to battaglia 2016 tau". For Battaglia16 the numbers are the same before and after. fb and units. Upstream rho_2d has no fb, and it multiplies by ρ_crit(z)/(1+z)^3/h^2 and r200c * (1+z). Read from the code, that is a comoving column, (1+z)−2 times the physical one (the h2 cancels against ne2d). 9f37b1e replaced both: rho_fit * model.f_b * rho_crit * r200c with physical ρcrit and R200c (XGPaint.jl/src/profiles_tau.jl:94, shown above). The fb is physically required, as the Battaglia (2016) Fig. A1 check above shows.

Numerical effect. Reading the two versions, the fork's projected Battaglia16 electron column is 0.9 fb(1+z)2 times upstream's: the fb and units from 9f37b1e, the 0.9 from e67a8a1. No report quantifies this ratio directly; it follows from the code. The painted Battaglia16 lies 6–9 times below the curve drawn in Lee22 (doc v4 Sec. 1) because of four factors: the fb (9f37b1e), the electron conversion XHmp/mper e of ne2d (upstream code), the fork's 0.9 (e67a8a1), and the exponent difference. The first three together give 1/(0.6016 fb) ≈ 10.6 at equal shape (TNG's fb = 0.157). The drawn exponent −(β−γ)/α falls faster than −(β+γ)/α and lowers the drawn curve by a radius-dependent factor, which brings 10.6 down to the 6–9 seen across the plotted radii. Painted, it is 3.5 % above TNG at 0.3 < x < 1 in the lower z = 0 bin of Fig. 1.5 and 28 % below it in the upper bin (model/TNG 1.035 and 0.722; verify_v4 models_grid/fig1_check.txt). It does not affect any Lee22 number.

1.10 C9, a painting fix: exact per-halo y profiles below z = 0.1

Symptom. The 2026-09-29 XGPaint audit compared the production y lookup tables with a direct line-of-sight integral. Above z = 0.1 they agree to ≤ 9 × 10-5 (B12) and 6 × 10-4 (Lee22). Below z ≈ 0.02 the interpolated outskirts are wrong by up to a factor 35 (LEE22_TSZ_VERIFICATION_20260929.md, Sec. 1). The cause is the redshift grid. The tables are tabulated on 256 nodes uniform in z from 0.001 to 5 (Δz = 0.0196) and interpolated with a cubic B-spline in log y. Near z = 0 the angular size θ200 ∝ 1/dA(z) changes by a large factor across the first cell, so a uniform-z spline cannot follow it. In integrated Y of the B12 map, the interpolated halos carry 2.71, 1.97 and 1.16 times their true Y at z < 0.005 (16 halos), 0.005–0.01 (68) and 0.01–0.0206 (766). At 0.0206–0.05 the ratio is 0.987 (9,028 halos) and at 0.05–0.1 it is 1.0001 (69,424). In total the excess is 0.54 % of the map's Y (0.43 % for the Lee22 map), concentrated at low ℓ (outputs/lee22_tsz_verification_20260929/verify_A_xgpaint_audit/v4b_lowz_impact.json).

XGPaint behaviour worked around (not edited): the profile_grid redshift nodes

The coarse grid is upstream XGPaint behaviour. Upstream main already has N_z=256, z_min=1e-3, z_max=5.0 with redshifts = LinRange(z_min, z_max, N_z). The fork's ce1d239 (2026-07-13) changed only the mass and angle defaults of profile_grid (N_logM 256 → 128, logM_min 11 → 12, N_logtheta 512 → 256; the same commit also changed thread-local storage), not the z grid. The Lee22 pressure cache, built after ce1d239, therefore has 128 mass nodes over log M = 12–15.7 and shape (512, 256, 128), with the 512 angles requested explicitly by the project's interpolator setup (N_logtheta=512 in the log). The older B12 cache has (512, 256, 256) over log M = 11–15.7. Both have the same 256 z nodes (selftest_600152.idark.log, lines 5–41). XGPaint was not changed. The workaround lives in the repository painter and uses fill_profile_slice!, the function XGPaint itself uses to fill each cache node. That function, with its per-(M, z) fast path prepare_profile_slice/evaluate_profile_slice, was added to the fork in e67a8a1 (2026-04-30). The Lee22 pressure type implements that fast path for itself (lee2022_tsz_pressure_profile.jl:66-79).

function fill_profile_slice!(dest, model::AbstractGNFW{T}, logthetas, mass, redshift) where T
    prepared = prepare_profile_slice(model, mass, redshift)
    @inbounds for itheta in eachindex(logthetas)
        theta = exp(logthetas[itheta])
        dest[itheta] = max(zero(T), evaluate_profile_slice(model, prepared, theta, mass, redshift))
    end
    return nothing
end


function profile_grid(model::AbstractGNFW{T}; N_z=256, N_logM=128, N_logtheta=256, z_min=1e-3,
        z_max=5.0, logM_min=12, logM_max=15.7, logtheta_min=-15.7, logtheta_max=2.5) where T

    logthetas = LinRange(logtheta_min, logtheta_max, N_logtheta)
    redshifts = LinRange(z_min, z_max, N_z)
    logMs = LinRange(logM_min, logM_max, N_logM)
    return profile_grid(model, logthetas, redshifts, logMs)

function ExactTable(model, mass, z, theta_min, theta200, theta_max; dlog=0.02)
    lo = log(max(theta_min, 1.0e-5 * theta200))
    hi = log(theta_max) + 1.0e-9
    n = max(8, ceil(Int, (hi - lo) / dlog) + 1)
    logtheta = collect(range(lo, hi, length=n))
    y = zeros(n)
    XGPaint.fill_profile_slice!(y, model, logtheta, mass, z)
    return ExactTable(logtheta, y)
end

function (t::ExactTable)(theta)
    lt = clamp(log(theta), first(t.logtheta), last(t.logtheta))
    k = clamp(searchsortedlast(t.logtheta, lt), 1, length(t.logtheta) - 1)
    f = (lt - t.logtheta[k]) / (t.logtheta[k + 1] - t.logtheta[k])
    y0, y1 = t.y[k], t.y[k + 1]
    return (y0 > 0 && y1 > 0) ? exp((1 - f) * log(y0) + f * log(y1)) : (1 - f) * y0 + f * y1
end
